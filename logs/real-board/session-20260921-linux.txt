Bug found: the ethernet MAC is wrong
------------------------------------
U-Boot:  "E17: station address 04:00:04:00:04:00 (from board PROM)"
Linux:   "e17-lance ... eth0: E17 ILACC at 0xfec68000, IRQ 205,
          MAC 04:00:04:00:04:00"

The board's real address is 00:00:5B:00:49:62 (ELTEC OUI), which RMON prints
in its banner and which is stored in the NVRAM board-ID block at
0xfec2048a.  Both U-Boot's and Linux's reads of the station-address PROM
around LANCE +0x1d01/+0x1d81 are producing 04:00:04:00:04:00 - a nibble/lane
extraction that is wrong, not a missing PROM.  DHCP still works (the server
hands out 192.168.2.221 regardless), but the board is lying about its
identity on the wire.

Console notes
-------------
The serial console is OUTPUT ONLY on this build: nothing typed at it reaches
the shell (CR, LF and CRLF all ignored; RMON, by contrast, echoes fine, so the
link and the bridge are good).  That is the CD2401 receive path, which is
exactly what the polled-mode work on e17-clean addresses.
`/init` therefore starts BusyBox telnetd, and scripts/e17sh.py is the way in.

telnetd blocks until "random: crng init done", which on this machine took
several minutes after boot - a connection refused/timing out right after boot
is that, not a dead network.
